# MIET Translator Pro — Rework v2

> Полный пересмотр концепции. От «один проход через одну vision-модель» к
> **каскадному конвейеру из 5 проходов с разными тирами моделей MiMo**.

---

## 1. Концепция в одном абзаце

На вход — `pdf / docx / pptx / zip / rar / 7z`.
Файл нормализуется в PDF (docx/pptx → PDF через LibreOffice). Дальше идёт
**пять последовательных проходов**, каждый со своей моделью MiMo, выбранной по
соотношению цена/качество. Результат — академический русский перевод с
нативными OMML-формулами и сохранёнными / перерисованными рисунками на белом
фоне; DOCX рендерится в браузере как настоящий Word (`docx-preview`), PPTX —
конвертируется в PDF и показывается через `pdf.js`.

---

## 2. Тиры моделей MiMo

Реальные модели и цены из официальной [pricing-таблицы Xiaomi MiMo](https://platform.xiaomimimo.com/docs/en-US/pricing):

| Tier        | Model            | Context | $/M in | $/M out | Когда используется                                       |
|-------------|------------------|--------:|-------:|--------:|----------------------------------------------------------|
| `OMNI_BEST` | `mimo-v2.5`      |     1M  | $0.40  | $2.00   | **Pass 1**: глобальный OCR + layout-карта всего документа |
| `OMNI_MID`  | `mimo-v2-omni`   |    256K | $0.40  | $2.00   | **Pass 2**: постраничный OCR (тот же тариф, меньше контекст — батч-друг)         |
| `REASON`    | `mimo-v2.5-pro`  |     1M  | $1.00  | $3.00   | **Pass 4**: академический перевод с рассуждением         |
| `CHEAP`     | `mimo-v2-flash`  |    256K | $0.10  | $0.30   | **Pass 3** (sverka pdfjs) + **Pass 5** (watchdog)        |

Тиры — это **роли**, не конкретные имена. Любой проход можно переключить через
`src/lib/pipeline/tiers.ts`.

## 3. Пятипроходный конвейер

```
┌──────────────┐
│  input file  │  pdf / docx / pptx / zip / rar / 7z
└──────┬───────┘
       │
       ▼
┌──────────────────────────────────────────────────────────────────┐
│  Normalize → PDF                                                  │
│   • zip/rar/7z → libarchive.js (WASM) → распаковка                │
│   • docx/pptx  → LibreOffice headless (server-side conversion)    │
│   • pdf        → as is                                            │
└──────┬───────────────────────────────────────────────────────────┘
       │
       ▼
┌──────────────────────────────────────────────────────────────────┐
│  Pass 1 · GLOBAL OCR + LAYOUT MAP             [mimo-v2.5  OMNI]   │
│   • вход: весь PDF (картинки страниц) одним запросом              │
│   • выход (JSON): layout-карта                                    │
│     { pages: [ { idx, kind: text|figure|table|chart|equation,     │
│                  bbox?, caption?, notes? } ] }                    │
│   • цель: понять структуру до постраничной работы — на каких      │
│     страницах есть формулы, рисунки, таблицы, графики             │
└──────┬───────────────────────────────────────────────────────────┘
       │
       ▼
┌──────────────────────────────────────────────────────────────────┐
│  Pass 2 · PER-PAGE OCR                       [mimo-v2-omni  OMNI] │
│   • вход: каждая страница как PNG + соответствующая часть         │
│     layout-карты из Pass 1                                        │
│   • выход (markdown + JSON-метки):                                │
│     - текст с $...$ / $$...$$ для формул                          │
│     - {{FIGURE:n}} / {{TABLE:n}} / {{CHART:n}} плейсхолдеры       │
│       с привязкой к bbox исходной страницы                        │
│   • параллелизм: 4-6 страниц одновременно                         │
└──────┬───────────────────────────────────────────────────────────┘
       │
       ▼
┌──────────────────────────────────────────────────────────────────┐
│  Pass 3 · PDFJS TEXT SVERKA                  [mimo-v2-flash CHEAP]│
│   • параллельно с Pass 2 (или сразу после): pdf.js извлекает      │
│     текстовый слой страницы                                       │
│   • вход во flash: (а) OCR-текст из Pass 2, (б) pdf.js текст      │
│   • выход: diff-патч — что OCR пропустил, что галлюцинировал,     │
│     какие формулы переврал. Подсказка идёт обратно в Pass 4.      │
│   • если pdfjs пусто (скан) — пропускаем, доверяем Pass 2         │
└──────┬───────────────────────────────────────────────────────────┘
       │
       ▼
┌──────────────────────────────────────────────────────────────────┐
│  Pass 4 · ACADEMIC TRANSLATION              [mimo-v2.5-pro REASON]│
│   • вход: merged-страницы (Pass 2 + sverka-патчи Pass 3)          │
│     + ЦОС-глоссарий, термины МИЭТ                                 │
│   • выход: финальный русский markdown с:                          │
│     - $...$ / $$...$$ для формул → пойдут в OMML                  │
│     - {{FIGURE:n}} плейсхолдерами на местах                       │
│   • батч по 8-12k токенов, чтобы не терять связность              │
└──────┬───────────────────────────────────────────────────────────┘
       │
       ▼
┌──────────────────────────────────────────────────────────────────┐
│  Figures / Charts                                                 │
│   • рисунки: pdfimages вырезает растровые → JPEG/PNG              │
│   • векторные графики (TikZ/PGFPlots/matplotlib-PDF): рендер      │
│     страничного crop по bbox из Pass 1 → PNG на белом фоне        │
│   • Python (matplotlib) для перерисовки графиков с русскими       │
│     подписями — отдельный server-side CLI tool                    │
└──────┬───────────────────────────────────────────────────────────┘
       │
       ▼
┌──────────────────────────────────────────────────────────────────┐
│  Pass 5 · WATCHDOG VERIFIER                  [mimo-v2-flash CHEAP]│
│   • вход: финальный перевод + исходный (pdfjs) текст              │
│   • задача: найти оставшиеся косяки                               │
│     - сырые LaTeX-команды в прозе (не обёрнутые в $)              │
│     - CJK-символы (记忆, 系统) которые модель иногда вставляет     │
│     - пропущенные подписи к рисункам                              │
│     - английские технические термины, не подменённые глоссарием   │
│   • выход: список патчей → применяются локально                   │
└──────┬───────────────────────────────────────────────────────────┘
       │
       ▼
┌──────────────────────────────────────────────────────────────────┐
│  Build & Render                                                   │
│   • DOCX:  docx@9 + LaTeX→OMML  (ГОСТ-стили: TNR 14pt, 1.5, поля) │
│   • PPTX:  кастомный builder поверх template.pptx                 │
│   • DOCX preview: `docx-preview` (в браузере, как Word)           │
│   • PPTX preview: server-side LibreOffice → PDF → pdf.js          │
└──────────────────────────────────────────────────────────────────┘
```

## 4. Что меняется в коде

### Новое

```
src/lib/pipeline/
  tiers.ts            # модели по ролям: OMNI_BEST / OMNI_MID / REASON / CHEAP
  normalize.ts        # ZIP/RAR/7z распаковка + docx/pptx → PDF (через server tool)
  pass1-layout.ts     # глобальный OCR-обзор → layout map
  pass2-pages.ts      # постраничный OCR
  pass3-sverka.ts     # сверка с pdfjs текстом
  pass4-translate.ts  # академический перевод
  pass5-watchdog.ts   # финальный QA-патч
  pipeline.ts         # оркестратор всех 5 проходов
  types.ts            # LayoutMap, PageOCR, SverkaPatch, etc.

src/components/
  DocxView.tsx        # рендер DOCX через docx-preview (Word-like)
  PptxView.tsx        # PPTX → server-converted PDF → pdf.js
```

### Меняется

- `src/lib/mimo.ts` — добавлены модели `mimo-v2-flash`, `mimo-v2.5-pro`,
  убрана старая FALLBACK_CHAIN, добавлена tier-aware обёртка.
- `src/components/Preview.tsx` — отделён от рендера DOCX/PPTX (вызывает новые
  компоненты).
- `package.json` — `docx-preview` зависимость.

### Уходит на потом / опционально

- Старые `docPlanner.ts` / `slidePlanner.ts` остаются как fallback на время
  миграции, помечены `@deprecated`.

## 5. Серверные tool'ы (требуют Node CLI или service)

Эти штуки нельзя сделать чисто в браузере. Они живут в `tools/cli/`:

| Tool                          | Что делает                              | Бинарник                |
|-------------------------------|-----------------------------------------|-------------------------|
| `convert-to-pdf.mjs`          | docx / pptx → pdf                       | `libreoffice --headless`|
| `redraw-figure.py`            | график → matplotlib на белом фоне       | `python3 + matplotlib`  |
| `extract-figures.mjs`         | растровые рисунки из PDF                | `pdfimages`             |

Web-приложение либо вызывает их через CLI offline, либо через лёгкий
edge-сервис (когда/если он появится).
